# Журнал решений

## [v1] Читатель — молодой, нахватавшийся; опытные вторичны
Первичная аудитория — студент, прошедший по верхам. Вторичная — опытные (быстрая карта). Аналогии держим точными ради вторых, паузой и заземлением — ради первых.

## [v1] Спина — буквы, не подсистемы
Учебник организован вокруг ~4 универсальных способов подключения; подсистемы — упражнения. Довод усилен: механизм подсистемы меняется между версиями, буква — нет.

## [v1] Подсистема = вплавление без границы + контракт
Несущая модель: подсистема растворяется в едином дереве конфигурации (нет `node_modules`), сразу по трём слоям (данные/код/интерфейс); контракт (буквы) — замена недостающей границе. Три лица: фреймворк / пакет / миграция схемы.

## [v1] Голос — разговорник: перевод, не разговор
Безлично, сравнение не оценка, без абсолютов, история нейтральна. Не оправдываемся за 1С — просто показываем то же самое.

## [v1] Метод объяснения — лесенка
Прогрессивный перевод: знакомый крючок + одна дельта на ступень; кульминация — «нет границы», она вручает буквы.

## [v1] Установка ≠ внедрение (рамка темы)
Установку (перенос частей БСП) делает обработка первого внедрения. Книга — про сцепку своих объектов (внедрение).

## [v1] Структура: Часть 0 — сердце
Часть 0 («Что такое подсистема») выросла из тонкого интро в концептуальный въезд (лесенка → граница → контракт). Дисциплина сопровождения (поддержка/обновление) повышена в отдельную часть.

## [v1] Решебник — припаркован ниже по течению
Вторая книга (по спросу), ссылается на учебник, спина = demand-индекс (S3). Собирается после учебника и S3.
