# Механизмы подключения к БСП — алфавит (S0)

Способы, которыми объект конфигурации подключается к подсистеме БСП. Выверено разбором: Контактная информация, Печать, Свойства, Управление доступом (RLS), Обмен данными (синхронизация), Дополнительные отчёты и обработки.

## Ключевой тезис

**Буквы универсальны, поверхности — от платформы.** Способов связать хост и расширение по сути всего несколько: хост *находит* тебя, ты *говоришь* хосту, хост *зовёт* тебя, плюс ты просто *пользуешься*. Пятый придумать трудно. Поэтому те же буквы есть в Django, Rails, Spring. От платформы 1С — только конкретные поверхности (переопределяемые модули, RLS-шаблоны, макеты), не сами буквы.

## Способы

### 0. Использование (не внедрение)
Зовёшь программный интерфейс БСП как обёртку над платформой; объект не трогаешь.
- Опознать: «вызовите такой-то метод», без «добавьте реквизит/подписку/объект».
- Примеры: Отправка SMS, Получение файлов из Интернета, Штрихкод.
- Мировое имя: использование библиотеки / SDK.

### 1. По структуре / соглашение об именах
Создаёшь у объекта предписанную структуру (ТЧ, реквизиты с точными именами) — БСП связывается с ней **по имени**. Имя и есть привязка. Нет структуры — БСП объекта не видит.
- Опознать: «создайте табличную часть `ИмяКонвенции` с реквизитами `Имя1`, `Имя2`…».
- Примеры: ТЧ `КонтактнаяИнформация` (КИ), ТЧ `ДополнительныеРеквизиты` (Свойства).
- Мировое имя: **Convention over Configuration** (Rails, Django).

### 2. Декларация (опиши — БСП действует)
Заполняешь процедуру/структуру, которая **возвращает описание** (состав, свойства, команды), а БСП по нему работает. Сам ничего не делаешь — декларируешь.
- Опознать: «перечислите в `…Переопределяемый`», «опишите в определяемом типе», «верните структуру `Сведения…`».
- Примеры: состав объектов печати, виды доступа RLS, набор свойств, персданные, назначение доп. обработок.
- Мировое имя: **декларативная конфигурация / metadata-driven**; самоописание артефакта = **манифест / дескриптор**; членство = **registration / registry**.

### 3. Императив / обработчики (БСП зовёт — ты действуешь)
Заполняешь предписанные точки; БСП вызывает твой код, и код **действует** — врезает в форму, формирует, проверяет, заполняет.
- Опознать: «в обработчике `ПриСозданииНаСервере`…», «добавьте экспортную процедуру `Печать`», подписки на события.
- Примеры: врезка КИ/Свойств в форму, процедура `Печать`, `ЗаполнитьНаборыЗначенийДоступа`.
- Мировое имя: **hook / callback**, под принципом **Inversion of Control** («не звоните нам, мы позвоним вам»). Подвиды: подписки ≈ **Observer / event listeners**; переопределение предписанных процедур ≈ **Template Method**.

## Именованные комбинации
Не отдельные буквы, а узнаваемые сочетания:
- **Подключаемые команды** = декларация команды + обработчик. ≈ **Command pattern**.
- **Печать** = декларация состава + декларация команд + императивная процедура + макет.

## Оси / фасеты (ортогональны способам)

- **Сложность поверхности декларации** (даёт оценку трудности и порядок учебника):
  список (КИ виды, Свойства наборы) → **DSL** (RLS — синтаксис ограничения в ролях) → **схема + правила во внешнем инструменте** (Обмен — регистрация + конвертация, авторятся в КД, ложатся макетами). ≈ DSL, ORM/ETL-маппинг.
- **Расширяемость в рантайме**: разработчик включает возможность, артефакты добавляет админ в рантайме без конфигуратора (Доп. отчёты и обработки). ≈ **plugin architecture / microkernel**; самоописание плагина = манифест.

## Поверхности декларации (где живёт «опиши»)
Переопределяемый модуль · модуль менеджера · определяемый тип · роли (RLS) · макеты.
Это *где*, не *что*: способ — «опиши», поверхность — где именно.

## Флаги данных
`уход_от_предопределённых` (наполнение через обработчики обновления + идентификаторы объектов вместо предопределённых элементов), `требует_РИБ`, `модель_сервиса` и пр. — не способы, а сквозные признаки.

## Мост к мировой практике

| Наша буква | В БСП | Мировое имя |
| --- | --- | --- |
| По структуре | ТЧ/реквизиты с конвенц. именами | Convention over Configuration |
| Декларация | переопределяемый модуль, опред. тип, `Сведения…` | declarative config, manifest, registry |
| Императив | `ПриСозданииНаСервере`, `Печать`, подписки | hook / IoC, Observer, Template Method |
| Подключаемые команды | механизм команд | Command pattern |
| Рантайм-расширяемость | Доп. отчёты и обработки | plugin architecture / microkernel |
| Лестница декларации | RLS, правила обмена | DSL, schema + mapping (ORM/ETL) |

## Как использовать в учебнике
Глава открывается **местным именем** (переопределяемый модуль) и тут же даёт **мировое** (это IoC, так же в Spring/Django). Два эффекта: возвращает 1С-разработчику достоинство фактом («ты всё это время писал hooks и Observer») и даёт переносимость (узнаёшь паттерн в любом чужом фреймворке).
