# Что такое подсистема — рабочая модель (canон для глав)

## Определение
Подсистема в 1С — переиспользуемая способность приложения, поставляемая как метаданные, которые **вплавляются в единое дерево конфигурации** сразу по трём слоям (данные, код, интерфейс) и несут **контракт** о том, как чужие объекты к ней подключаются.

## Стержень: нет границы
В пакетном мире библиотека лежит в своей папке (`node_modules`) — отдельно. В 1С такой границы нет: подсистема растворяется в одном дереве с приложением, её объекты структурно неотличимы от твоих. Отсюда всё:
- внедрить = **слияние**, а не копирование;
- обновить = слияние заново, поверх правок (боль обновления);
- **буквы = замена недостающей границе**: трогать чужое только через санкционированные точки (переопределяемые, подписки, расширения), чтобы своё осталось отделимым.

## Три лица одного
- **фреймворк** — зовёт тебя (контракт, буквы);
- **пакет** — зависимости, порядок, предпосылки;
- **миграция схемы** — слой данных меняет твою БД (под схемой — данные → миграция, не копия).

## Три слоя
Данные (метаданные → таблицы) · код (модули) · интерфейс (формы, команды). Стык трёхслойный; буквы режут поперёк слоёв.

## Установка ≠ внедрение
Установку (перенос частей БСП) делает обработка первого внедрения — гранулярно, с учётом взаимосвязей, для greenfield. Внедрение (сцепка твоих объектов) — ручное, про него книга.

## Буквы долговечнее версий
Механизм подсистемы со временем меняется (печать: внешние обработки → расширения). Буква — нет. Поэтому учим грамматику, а не шаги.

## Метод объяснения — лесенка
Прогрессивный перевод: знакомый крючок + одна дельта на ступень, кульминация «нет границы» вручает буквы. Голос — безличный перевод, сравнение не оценка, без абсолютов, история нейтральна.
